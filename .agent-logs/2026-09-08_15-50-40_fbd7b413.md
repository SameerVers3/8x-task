`INFERENCE_API_KEY` is a **pass-through API key** for the upstream providers (Pollinations.ai, JSON2Video), not a key for the relay itself.

Here's how it flows:

1. **App** (`/app/config/inference.ts`) sends `X-API-Key: <INFERENCE_API_KEY>` to `http://localhost:8000`
2. **Inference relay** (`/inference/routes/image.py`) receives it via the `X-API-Key` header
3. **Relay forwards it** to the actual provider (e.g., Pollinations.ai or JSON2Video)

So if you set `INFERENCE_API_KEY=your-pollinations-key`, your images get generated via your Pollinations account. If you leave it blank, the relay falls back to its own defaults (`POLLINATIONS_API_KEY` / `JSON2VIDEO_API_KEY` from the inference `.env`).

### When do you need it?

| Scenario | What to do |
|----------|-----------|
| **Just testing locally** | Leave it blank — the relay has its own defaults |
| **Using your own Pollinations account** | Set `INFERENCE_API_KEY` to your Pollinations API key |
| **Private generation** | Pollinations requires a key for `private: true` requests |
| **JSON2Video** | JSON2Video requires a key entirely (no free tier) |

### The relay's own defaults

In `/inference/.env`:
```bash
POLLINATIONS_API_KEY=your_api_key_here   # relay's fallback for pollinations
JSON2VIDEO_API_KEY=your_key_here           # relay's fallback for json2video
```

So the relay supports **two ways** to pass provider keys:
- **App-level**: `INFERENCE_API_KEY` in `/app/.env` (sent per-request)
- **Relay-level**: `POLLINATIONS_API_KEY` / `JSON2VIDEO_API_KEY` in `/inference/.env` (relay fallback)

If you set both, the app-level key **wins** because it overrides the relay's default.

---

**Bottom line:** For local development, you can leave `INFERENCE_API_KEY` empty. For production or if you want to track usage under your own accounts, set it to your provider's key.
